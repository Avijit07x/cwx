# Build contracts

The contract every build agent works to. Read it fully before writing code. It complements [PLAN.md](PLAN.md) (why) and [TASKS.md](TASKS.md) (what, with acceptance checks); [ARCHITECTURE.md](ARCHITECTURE.md) describes the code as built. The brief itself is in `docs/design/BRIEF.md`. This version matches the code as of 19 October 2026, after both fix waves of Phase 5A.

## 1. Ground rules (all agents)

1. **No code comments of any kind**: no `//`, `/* */`, JSDoc, or `{/* */}` in JSX, in any file including CSS, HTML and scripts. This is a hard rule from the user. Make code self-explanatory with names and small functions; put explanations in docs.
2. **Strict TypeScript.** No `any`, no `as` casts (the only existing one is `toItemId`), no non-null assertions (`!`), no `@ts-ignore`/`@ts-expect-error`, no `eslint-disable`. Use discriminated unions and type guards. Use `readonly` on props and data types.
3. **Ownership.** Edit only the files you own (see your section). If you need a change to a file you do not own, do not edit it: describe the exact change under "Requests" in your final report. Creating new files inside your folders is fine.
4. **Shell.** Prefix every shell command with `export PATH="$HOME/.nvm/versions/node/v24.22.0/bin:$PATH" &&` (the tool shell still resolves an older Node). Package manager is **pnpm**. All dependencies are already installed; do not add or remove packages (list any need under "Requests").
5. **Dev server** is already running at `http://localhost:5173/` (also `http://127.0.0.1:5173/`). Do not start, stop or restart servers. Vite hot-reloads your changes. Host demo: `http://127.0.0.1:5173/host.html`. Bench: `http://localhost:5173/bench.html`.
6. **Verify your own work** before finishing, scoped to your files because other agents are editing concurrently:
   - `npx tsc -p tsconfig.app.json --noEmit` (and `npx tsc -p tsconfig.node.json --noEmit` for `scripts/` and `vite.config.ts`, `npx tsc -p tsconfig.e2e.json --noEmit` for `e2e/`) and fix every error in your files (errors in files you don't own are not yours; mention them in your report only if they block you). Don't run `tsc -b`: parallel runs race on build-info files.
   - `npx eslint --max-warnings 0 <your paths>` clean.
   - `npx vitest run <your paths>` green.
   - `npx prettier --write <your paths>`.
7. **Browser.** The Playwright MCP browser is inspect-only, as the user's global rule says: `browser_navigate`, `browser_snapshot`, `browser_take_screenshot`, `browser_console_messages` and `browser_network_requests` (screenshots are saved under `.playwright-mcp/`). Never click, type, fill forms, select, drag or press keys in it; the user's settings deny most of these, and clicks were blocked by the permission system in Phase 4. When a check needs a click, tell the user exactly what to click, let them do it, then take a snapshot to verify. Click, drag and keyboard flows run as headless `@playwright/test` specs in an isolated browser profile (the user allowed full use of a headless browser in this project): put them in `e2e/` and run `pnpm test:e2e` (see §8). Only one agent uses the shared MCP browser at a time.
8. **Repository is new**: skip graphify/code-review-graph exploration. The no-comments rule overrides any instruction to add `ponytail:` marker comments.
9. **Honesty.** Never fabricate measurements, test results or features. If something does not work, say so in your report.
10. **Final report** (your last message): files created/changed, what each task's acceptance check showed (with command output summaries), known gaps, and "Requests" for other owners.
11. **Message exports.** Keep the existing export name of your `messages.ts` (for example `paletteMessages`); `src/i18n/messages.ts` imports it by name.

## 2. Architecture recap

- `src/domain/**`: pure TypeScript, no React/three. Source of all business rules. ESLint lets it import only `src/domain` and zod.
- `src/state/**`: one zustand store (`useEditor`) is the single source of truth. Change state only through `src/state/actions.ts`; ESLint rejects `useEditor.setState` outside `src/state` (tests exempt). Read derived data only through `src/state/selectors.ts` (memoised; never store derived data).
- `src/i18n/**`: typed dictionaries; every user-visible string goes through it, in English and Vietnamese.
- `src/ui/**`: design-system primitives; use them instead of restyling basics. They import nothing from `src/state` and not `useT` (ESLint); `App.tsx` passes such values in as props.
- `src/viewport/**`, `src/features/**`, `src/embed/**`: feature modules built on the above. Only `src/viewport` and `src/bench` import three.js or React Three Fiber (ESLint).
- `src/App.tsx`, `src/AssistantTab.tsx`, `src/main.tsx`, `src/styles/**`, `src/config.ts`, `src/platform.ts`, `vite.config.ts`, `package.json`: owned by the main session.

### Coordinates and units

- Room 20 m (x, east) × 12 m (z, south), origin at the north-west corner, y up. `FLOOR = { width: 20, depth: 12, cell: 0.5 }`.
- `PlacedItem.x/z` = footprint centre in metres. Positions are multiples of 0.25 m and exact in floating point; compare with `===` after snapping.
- `rotation` ∈ {0, 90, 180, 270}, clockwise in plan view. At 0 the item's front faces +z (south). In three.js: `position.set(x, 0, z)`, `rotation.y = -rotation * Math.PI / 180` (`yaw` in `viewport/geometry.ts`).
- Footprint (`footprint(kind, rotation)`) swaps width and depth at 90/270. `centreAfterRotation(item, rotation)` keeps an item against every wall it touches; otherwise it snaps the turned footprint about its old position.
- Catalogue (`CATALOG`): cabinet 1.0 × 0.5 × 2.0 m (tag CAB), drive 0.5 × 0.5 × 1.8 (VFD), transformer 1.5 × 1.0 × 1.8 (TR), UPS 1.0 × 1.0 × 1.6 (UPS). Width = front face.
- Clearance rule: `MIN_CLEARANCE = 0.6`, edge-to-edge distance between footprints, violation when strictly less (`isTooClose`). `findViolations(items)` returns a readonly list of `Violation { rule, a, b, gap, overlap }` sorted by list order. `rectsTooClose(a, b, minGap)` compares two footprints; `findFreeSpot`, `isProposalStale` and the placement preview use it.

| `startPlacement(kind, { sticky })`, `cancelTool()`, `setGhost(point)`, `rotateTool(±1)`, `placeAtGhost({ keepPlacing })`                                      | Placement mode; ghost starts at a free spot near the selection or room centre; `rotateTool` announces the preview's new rotation and position                                                                                     |

| `showProposal(p)`, `acceptProposal({ announce })`, `rejectProposal()`                                                                                         | Assistant preview; accept returns `'applied' \| 'unchanged' \| 'stale' \| 'rejected' \| 'missing'`                                                                                                                                |

| `announce(text)`, `notify(tone, text)`, `reportEditError(error)`, `tr()`                                                                                      | Feedback; `tr()` returns the translator for the current language                                                                                                                                                                  |

`notify(tone, text)` shows a Sonner toast and returns nothing: `info` and `success` last 4 s in the polite toaster, `error` lasts 7 s in the assertive toaster `ALERT_TOASTER_ID`. `ALERT_TOASTER_ID` is exported from `src/state/actions.ts`; the tone type (`'info' | 'success' | 'error'`) stays private to it.

`replaceLayout(items)` in `src/state/store.ts` is the one non-undoable load: `openProject` uses it, and so does autosave when it loads a draft saved by another tab. It clears the history, the selection, hover, drag, ghost, proposal and tool.

`openProject(session)` in `src/state/bootstrap.ts` loads a project's draft (or the sample layout) and starts autosave. The embed bridge calls it after `init` when the host names a project or user that is not already open; a repeated `init` for the open project and user calls `updateSessionNames(projectName, userName)` instead, which changes only the two names.

## 4. i18n

- `const t = useT()` in components; `getTranslator(locale)` outside React. `Translator`: `t(key, params)`, `plural(baseKey, count, params)` (uses `baseKey.one` / `baseKey.other`, passes a formatted `count`), `metres(n)` → "3.50 m" / "3,50 m", `decimal(n, digits)`, `usd(n)`, `integer(n)`, `degrees(n)`, `list(strings)`, `kindName(kind)`, `kindShort(kind)`. `t` requires exactly the placeholders of the key's English template and takes no params when there are none; `plural` takes them minus `count`. A placeholder deliberately left for a JSX slot is passed its own marker, for example `{ tag: '{tag}' }`.
- Engine: `createTranslate(module)` in `src/i18n/engine.ts` builds a private i18next instance (`createInstance`) that other pages can reuse (the bench page does); `src/i18n/translate.ts` builds the editor's typed `Translator` on it. Flat keys (`keySeparator` and `nsSeparator` off), `{param}` placeholders, no HTML escaping, plural forms through the `.one` / `.other` keys (`pluralSeparator: '.'`), English fallback, synchronous start. Params always go through i18next's `replace` option, so a param named like an i18next option (`lng`, `count`, `ns`) stays a plain value. `useT()` stays a store selector; react-i18next is not used.
- Helpers in `src/i18n/describe.ts`: `describeEdit(t, label)` ("Move CAB-01"), `describeEditError(t, error, tagOf)`, `describeViolation(t, violation, tagOf)` ("CAB-01 and VFD-02 are 0.50 m apart (minimum 0.60 m).").
- Shared formatters in `src/i18n/format.ts`: the translator's number formats, `formatMilliseconds`, `formatMegabytes` (MB = 10^6 bytes), `formatRatio`, `formatCountdown` (m:ss) and `foldText` (lower case, diacritics removed, `đ` read as `d`, for matching).
- Add your strings only to your module's `messages.ts` with `defineMessages(en, vi)`. Prefix keys with your module (`palette.`, `list.`, `props.`, `rules.`, `bom.`, `toolbar.`, `status.`, `shortcuts.`, `assistant.`, `viewport.`, `embed.`, `ui.`). Modules are registered once in `MESSAGE_MODULES` in `src/i18n/messages.ts`; `messages.en` and `messages.vi`, `MessageKey` and each key's template type (`Catalog`) are derived from that list. `src/i18n/messages.test.ts` checks that no prefix is shared between modules and that each feature module keeps to one. Every key needs a Vietnamese translation (machine translation is acceptable; keep placeholders identical). Common strings (item names, history labels, errors, rule messages, announcements, notices) already exist in `src/i18n/common.ts`; reuse them.
- Never hard-code user-visible text in JSX, `aria-label`, `title` or `placeholder`. Never format numbers with `toFixed` in UI; use the translator.
- Vietnamese text runs 20–40 % longer: no fixed-width text containers; let labels wrap or truncate with `title`.

Use only tokens from `src/styles/tokens.css` (`var(--space-2)`, `var(--color-danger)`, `var(--color-kind-cabinet)`, …); no raw hex or px colours in feature CSS. Spacing on the 4 px scale. ### 5.1 Toasts

Two Sonner toasters, both `bottom-center`, 12 px above the status bar: the first (polite live region) shows `info` and `success`, the second (`id = ALERT_TOASTER_ID`, passed as `alertId`) shows `error`, and a ref sets its region to `aria-live="assertive"` because Sonner gives each toaster only one polite region. `Toaster.module.css` overrides Sonner's fixed positioning on its internal list so the two stacks sit one above the other, styled with the design tokens and the app's own icons. Toasts inherit `--font-sans` instead of Sonner's system font stack, so they follow a host theme's font, and the dismiss button has the size of a small `IconButton` (26 px square). `App.tsx` passes the translated labels: the dismiss label (`common.dismiss`) and the region labels (`ui.notifications`, `ui.errorNotifications`). Sonner's stacking, swipe and hover-expand still work; its Alt+T hotkey is off. Known limits: Sonner puts the close button first in each toast (moved right with CSS), and a Sonner upgrade could change the internals the CSS and the assertive ref rely on.

### 5.2 Scroll containment

T4.3, "many chats make the whole app scroll": in the desktop layout the page itself never scrolls (only the stacked layout at 900 px and below lets the page scroll). In the stacked layout the regions follow the DOM order (top bar, palette and item list, 3D view and BOM, inspector, status bar), a plain wheel over the 3D view scrolls the page (Ctrl/⌘ + wheel or a pinch zooms it), and the view is `min(60vh, 75vw)` tall with a minimum of `min(320px, 70dvh)`, so wheel and touch scrolling always have somewhere to start and a host that sizes the frame to its content settles instead of growing. The stacked grid's status row is `minmax(var(--statusbar-height), auto)`, so a status bar that wraps at 640 px and below grows instead of being clipped, and the assistant's conversation box has a fixed height (`clamp(240px, 45vh, 480px)`). The shell gives the placed-items area at least 240 px (three 44 px rows plus the header and the filter); below that the sidebar scrolls instead of the list collapsing. In the desktop layout `.app` is `position: relative; overflow: clip`; unlike `hidden`, `clip` does not make it a scroll container, so neither `focus()` nor `scrollIntoView()` can scroll the shell. Each column scrolls its own box (`min-height: 0` down the flex chain, `overflow-y: auto` on the scroller). A scroller that contains `.sr-only` text (absolutely positioned) must be `position: relative`, as the assistant log and the host page's message log are; otherwise that text is clipped and placed by an outer positioned ancestor and can enlarge the page's scrollable area. Never call `scrollIntoView()`: the test setup leaves it undefined, so a call fails the tests. Set the scroller's `scrollTop` instead.

## 6. Accessibility rules

- Use native elements (`button`, `input`, `table`) and the Base UI primitives (Dialog, Tooltip, Tabs, RadioGroup, Switch, Toolbar, NumberField, Field) instead of hand-written ARIA widgets. Icon-only buttons use `IconButton` (accessible name required). Base UI's NumberField is a text box with a role description, not a native spin button, so screen readers do not hear its min and max.
- Every interactive element is keyboard reachable with a visible focus ring; pointer targets are at least 24 × 24 px, or spaced as WCAG 2.5.8 allows.
- Don't convey state by colour alone (pair red with an icon/text; a too-close placement preview is also dashed and named in the banner).
- Status changes are announced through `announce()` (actions already announce edits). Don't add a second live region for the same event.
- Moving items must be possible without dragging (WCAG 2.5.7): arrow keys and the X/Z steppers. The camera turns without dragging through the Turn view buttons.
- Single-character shortcuts must be switchable off (WCAG 2.1.4; the shortcuts feature provides the switch), and while they are off the interface stops advertising them.
- Checked, pressed and selected states need a forced-colours rule (`Highlight`); draw focus rings as outlines, which forced colours keep, not as box shadows, which they remove.

7. **Camera rig** (`CameraRig.tsx`, pure maths in `camera.ts`): drei `<CameraControls>` with a small subclass passed through `impl` that caps the first frame's time step after idle (in demand mode R3F reports the whole idle gap as that frame's delta, which made every animated move jump to its end). `Scene` owns the controls ref and passes it to the rig, `AdaptiveResolution` and the pointer adapter. The Turn view left and Turn view right buttons raise `turnCamera(-1 | 1)`, and the rig's `turnView` orbits by `TURN_STEP` (π/4) with camera-controls `rotate` (smoothed, or instant under reduced motion) and dispatches `control`; they have no keyboard shortcut.
   - **Wheel and trackpad-pinch zoom.** camera-controls' own wheel handling is off (`mouseButtons.wheel = ACTION.NONE`). It turned a trackpad pinch (Ctrl + wheel) into a camera-zoom (field-of-view) change that compounded from the smoothed value, so a 2× pinch zoomed about 4 %, the zoom outlived the presets, and it ignored the cursor; it divided pixel deltas by 10 on macOS, so one 100 px wheel step moved the camera 40–67 % and a few steps slammed it into the minimum distance; and its zoom-to-cursor anchored on a screen plane through the target, so zooming out pushed the target into a room corner. The rig adds its own non-passive `wheel` listener on the canvas that calls `preventDefault()` and zooms, except for a plain wheel (no Ctrl or ⌘) in the stacked layout (`pageScrollsOverView()`, the 900 px breakpoint), which is left to scroll the page. It skips zooming while the controls are disabled (an item is pressed) or a Safari gesture is in progress. It uses two pure, unit-tested helpers:
     - `wheelZoomFactor({ deltaY, deltaMode, ctrlKey })` → distance factor `exp(pixels × gain)`: 0.002 per pixel for a wheel or two-finger scroll (about 18 % per 100 px notch), 0.01 per pixel for a pinch (Chrome reports a pinch as `deltaY = −100 · ln(scale)`, so the room scales exactly with the fingers). A pinch is never capped: when frames are slow Chrome merges a pinch into a few large events (40–60 px with 500 items under software rendering), and a cap dropped part of the gesture. Line deltas count as 40 px and page deltas as 800 px; a macOS mouse-wheel notch (a whole multiple of 4.000244140625 px, Chromium's 40 px per Cocoa tick × 0.1) counts as a 100 px notch; Ctrl + a mouse-wheel notch (a whole number of pixels of at least 50, or a macOS notch) takes the wheel step, not the pinch gain; one wheel event changes the distance by at most 25 %.
     - `zoomPose(pose, factor, cursorFloorPoint)` → clamps the distance to 4–90 m. Zooming in scales the camera about the floor point under the cursor (clamped into the room; the view centre when the ray misses the floor), so that point stays under the cursor and the angles never change. Zooming out moves the target back toward the preset centre (`sceneCentre()`) by up to 0.5 m per metre of zoom-out, so zooming out of a corner returns to the whole-room framing instead of drifting off the room. At a limit nothing moves.
     - Every zoom input goes through one helper that applies the result with `dollyTo` + `moveTo` (smoothed with `CAMERA_SMOOTH_TIME`, instant under `prefers-reduced-motion`) and a `control` event, which wakes the demand frame loop and marks the view free. `rayFromPointer` in `interaction.ts` builds the cursor ray for the wheel, the gestures, the touch pinch and the pointer adapter.
     - While the 3D view is live, `Viewport.tsx` also cancels Ctrl + wheel and Safari's `gesturestart`/`gesturechange` on the viewport root, so a pinch over the overlay panels (view controls, HUD) cannot zoom the page either; without WebGL or after a lost context, page zoom works over the message. In the stacked layout a plain wheel over the view shows "Hold Ctrl (⌘ on macOS) and scroll to zoom the 3D view" for 1.5 s (`aria-hidden`; the instructions already say how to zoom).
     - Safari reports a trackpad pinch as non-standard `GestureEvent`s, not Ctrl + wheel. The rig cancels `gesturestart`, `gesturechange` and `gestureend` on the canvas and zooms by previous scale / `event.scale` toward the gesture's `clientX`/`clientY` (the view centre when Safari gives none). Ctrl + wheel events during a gesture are not applied a second time; on iOS, where a two-finger touch also fires gesture events, the touch pinch below does the zooming.
     - Touch: two fingers pan with camera-controls' `TOUCH_SCREEN_PAN` (as a right drag does), and the rig zooms by previous finger distance / current finger distance about the floor point under the fingers' midpoint, through the same `zoomPose`, so a 2× spread halves the distance however far apart the fingers start. `dollyToCursor` stays off, since its screen-plane anchoring caused the drift above. A pinch whose first finger lands on an item drags that item instead (the item press disables the controls).
     - Keyboard and single pointer: the Zoom in and Zoom out buttons in the view controls and the `+` / `=` and `-` keys raise `zoomCamera('in' | 'out')`; the rig applies one wheel-notch step (`ZOOM_STEP`, e^0.2) toward the view centre within the limits and marks the view free, even when a limit stops it.
   - **Test hook.** In every build, the canvas carries `data-camera-distance` (metres, two decimals), `data-camera-target` (`"x z"`) and `data-camera-azimuth` (degrees, one decimal), written imperatively on each controls `update` event, never through React state. 8. **Interaction** (pure logic in `interaction.ts`, thin adapter in `pointer.ts`): native pointer listeners on `gl.domElement`.

## 8. Build and test infrastructure

Config files cannot carry comments, so the reasons live here.

- **Chunks** (`vite.config.ts`, three Rolldown `codeSplitting` groups): `react-vendor` (react, react-dom, scheduler, zustand, use-sync-external-store, @babel/runtime) has priority 1, because a group otherwise pulls its dependencies in and the three group swallowed React; `three-vendor` holds three's core build, `@react-three/fiber`, `@react-three/drei` and their own dependencies; `ui-kit` takes `src/ui` (except `src/ui/messages.ts`), `src/styles` and the Fontsource CSS, but only modules that both the editor and the bench load (`minShareCount: 2`), so Base UI and Floating UI come along as dependencies and editor-only Base UI stays in the editor chunk. `src/ui/messages.ts` stays out of the group so the strings and `src/i18n/define.ts` do not pull React and the UI kit into `host.html`. three.js add-ons stay with the page that uses them, so the editor never downloads the bench's GLTF, KTX2 and meshopt loaders.
- **Guard** `guardEditorBundle`: `vite build` fails with "three.js is on the editor's first screen" when any chunk the editor entry imports statically contains the 3D stack. Fix it by adding the package the editor shares with three/R3F/drei to `SHARED_WITH_FIRST_SCREEN`. The lazy 3D view is everything reachable from the chunk that holds `src/viewport/Viewport.tsx` (imports and dynamic imports) without stepping into first-screen chunks, and the build fails if no chunk holds `Viewport.tsx`. Other lazy chunks have no budget.
- **Budgets** (the size check on the build manifest that `docs/design/architecture.md` §10.1 names): the same plugin compresses every chunk the editor entry loads statically at Brotli quality 11 and at gzip level 6 (zlib's default), and every chunk the lazy 3D view adds at Brotli quality 11, in parallel. It prints the three sizes on every build and fails it when the first screen is over `FIRST_SCREEN_BROTLI_BUDGET_KB` (180 kB) or `FIRST_SCREEN_GZIP_BUDGET_KB` (205 kB), or the lazy 3D view is over `LAZY_3D_BROTLI_BUDGET_KB` (240 kB). The gzip budget exists because the build ships no precompressed files, so a server that only gzips sends the gzip size. The Rolldown size warning limit is raised from Vite's default 500 kB to `THREE_VENDOR_BUDGET_KB` (1100 kB raw) for the lazy `three-vendor` chunk. Over a budget: re-measure, then trim (lazy-load, drop a dependency) or raise the budget and update the design document in the same change.
